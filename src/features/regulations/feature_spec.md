# E:YUM 식품 규제·필수 서류 체크리스트 기능 명세

담당자 유정현 · 최종 수정일 2026-11-27 · 상태 초안

## 1. 목적과 범위

- 이 기능을 쓰는 사람과 상황은?
  - 혜윰 수출 담당자가 제품을 등록한 뒤 첫 상업 수출을 준비할 때 쓴다.
  - 담당자는 대시보드 공통 상단에서 수출 대상국을 고르고, 규제 탭에서 제품을 고른다. 화면에서 그 수출 대상국에 필요한 서류·절차와 준비 담당자, 추가로 확인할 제품 정보를 본다.
- 사용자가 이 탭에서 끝낼 수 있어야 하는 업무는?
  - 선택 국가의 현지 품목코드 후보를 확인한다.
  - 서류·절차마다 적용 상태(필수 / 판정 대기 / 해당 없음), 준비 담당자, 준비 시점을 확인한다.
  - ‘판정 대기’ 항목에서 어떤 정보가 왜 부족한지 확인하고, 제품 관리 탭이나 혜윰에 요청할 내용을 정리한다.
- 이번 시연에 포함할 범위는?
  - 시연 제품: 컵또떡 (제품코드 `cup-ttok`)
  - 수출 출발국: 한국
  - 수출 대상국: 싱가포르, 프랑스. 프랑스는 프랑스 본토가 EU 최초 입국지라고 가정한다.
  - 범위: 선적 전 규제 스크리닝과 체크리스트 안내까지
  - 범위 밖: 실제 세관 신고와 허가 신청. 이 일은 현지 수입자·신고대리인·운송인이 진행한다. 이 탭은 신고를 대신 제출하지 않는다.
  - 공식 기관의 실시간 외부 API 제공이나 연동 완료를 전제로 하지 않는다. 공식 자료의 보관·갱신 방식은 7. 미정 사항에 둔다.

## 2. 사용자 흐름

| 단계 | 사용자 동작 | 화면에 표시할 결과 |
|---|---|---|
| 1 | 공통 상단에서 수출 대상국을 고른 상태로 규제 탭에 들어온다 | 공통 상단에서 이미 고른 수출 대상국(싱가포르 또는 프랑스)을 그대로 유지해 표시한다. 규제 탭에서 수출 대상국을 다시 고르게 하지 않는다. 수출 출발국은 한국으로 표시한다. 공통 상단에 수출 대상국이 없으면 상단에서 고르도록 안내한다. |
| 2 | 아직 제품을 고르지 않았다 | 체크리스트 영역만 대기 상태로 두고 제품 선택 안내(“제품을 먼저 선택하세요”)를 보여준다. 선택된 수출 대상국 표시는 유지한다. |
| 3 | 컵또떡을 선택한다 | 구성품 요약(떡볶이떡-S 100g × 1, 파우더B 10g × 1)과 확인 상태 요약(확인됨 / 확인 필요 / 미확인 개수)을 보여준다. 이어서 선택된 수출 대상국 기준으로 현지 품목코드 ‘후보’와 그 출처, ‘기본 선적서류’ 목록, 수출 대상국별 서류·절차 목록을 보여준다. HS나 원재료 일부가 미확인이어도, 그 정보 없이 판단할 수 있는 기본 서류는 먼저 보여준다. |
| 4 | ‘판정 대기’ 항목을 연다 | 부족한 정보, 확인할 구성품, 판정 대기인 이유, 공식 근거와 확인일을 보여준다. |
| 5 | 공통 상단에서 수출 대상국을 바꾼다 | 제품 선택(컵또떡)은 유지한다. 품목코드 후보, 서류 목록, 근거를 새 수출 대상국 기준으로 다시 그린다. 이전 수출 대상국의 서류는 남기지 않는다. |
| 6 | 체크 완료 표시·저장·다시 열기 | 미정. 저장, 결과 이력, 재접속 시 복원은 팀 합의 전까지 구현하지 않는다. |

## 3. 입력

자료 출처는 채주현 담당 제품 탭의 규제용 API `GET /api/products/{제품코드}?for=규제&external=1`이다. 컵또떡은 `GET /api/products/cup-ttok?for=규제&external=1`로 받는다. 이번 응답은 실제 DB 등록 전 예시 데이터 모드에서 받은 값이다.

읽는 규칙은 다음과 같다.

- 제품 정보는 `fields` 배열에서 읽고, `status`와 `usable`을 함께 본다.
  - `confirmed`는 확인된 값이므로 판단에 사용한다.
  - `not_applicable`은 해당 없음으로 처리한다.
  - `needs_check`, `missing`, 또는 `usable:false`인 값은 화면에 참고로만 보여주고 판정 근거로 쓰지 않는다.
- 구성품별 양·원재료·하위 원료는 `components` 배열에서 읽는다.
- 값이 ‘없음’이거나 하위 원료 배열(`children`)이 비어 있어도 확인 상태를 건너뛰지 않는다. 비어 있는 배열은 ‘하위 원료 없음 확인’이 아니다.

| 항목 | 입력 주체·자료 출처 | 형식·단위 | 필요한 조건 | 누락·미확인 시 동작 |
|---|---|---|---|---|
| 제품 선택 | 사용자 / 제품 목록 | 제품코드 문자 (예: `cup-ttok`) | 항상 | 선택 전에는 제품 선택 안내만 보여준다. |
| 수출 대상국 | 사용자 / 대시보드 공통 상단에서 선택한 값 | 국가 (싱가포르 / 프랑스) | 항상 | 규제 탭에 들어올 때 공통 상단의 값을 그대로 유지한다. 값이 없으면 공통 상단에서 고르도록 안내한다. |
| 수출 출발국 | 고정값 | 국가 (한국) | 항상 | 한국으로 고정한다. |
| 운송 방식 | 사용자 (입력 위치는 미정) | 해상 / 항공 | 운송서류 이름을 정할 때 | 미선택이면 “해상이면 B/L, 항공이면 AWB”를 함께 안내한다. |
| 구성품과 양 | 제품 API `components[].name·amount·unit·quantity` | 문자, g, 개 | 항상 | 컵또떡은 떡볶이떡-S 100g × 1, 파우더B 10g × 1. 구성품이 없으면 구성품별 판단을 모두 ‘판정 대기’로 둔다. |
| 보관 조건 | 제품 API `product.storage_condition` | 문자 (상온 등) | 위생서류·검사 요건 판단 시 | 컵또떡 예시는 ‘상온 / confirmed’. 미확인이면 보관 조건이 필요한 항목만 ‘판정 대기’로 둔다. |
| 완제품 제조국 | 제품 API `product.finished_country` | 국가명 | 제조국 표시·서류 판단 시 | 컵또떡 예시는 ‘대한민국 / confirmed’. 통관상 원산지와 같은 값으로 취급하지 않는다. |
| HS 6자리 | 제품 API `export.hs6` | 6자리 숫자 | 현지 품목코드 후보 조회 시 | 컵또떡 예시 API는 비어 있음(`missing`). 아래 ‘과거 신고 이력’이 있으면 후보 조회에만 쓴다. 둘 다 없으면 코드 조회만 대기하고 기본 서류는 계속 보여준다. |
| 과거 한국 신고코드 | 혜윰이 별도로 알려준 값 (입력 경로는 미정) | 10자리 HSK (예: 1901.90-9091) | HS 6자리가 없을 때 | 공통 6자리 190190만 출처 ‘과거 신고 이력’으로 밝혀 후보 조회에 쓴다. API에 HS가 입력됐다고 표시하지 않는다. 현지 신고코드로 확정하지 않는다. |
| 떡 공장 증숙 여부 | 혜윰 회신 (제품 API에 칸 없음, 입력 경로는 미정) | 예 / 아니오 / 미확인 | 수입 당시 떡의 가공 상태와 품목코드 후보 판단 시 | 현재 미확인. 가공 상태가 필요한 품목코드 후보와 관련 항목만 ‘판정 대기’로 두고 이유를 보여준다. 동물성 원료 판단에는 쓰지 않는다. |
| 구성품별 원재료 | 제품 API `component.{구성품}.ingredients`, `components[].ingredients` | 원재료명·원산지·첨가물 여부·INS·알레르기 | 지정 품목 조건, 위생서류 판단 시 | 떡볶이떡-S와 파우더B 모두 ‘확인 필요 / usable:false’. 값은 참고로만 보여준다. |
| 하위 원료 | 제품 API `components[].ingredients[].children` | 배열 | 복합 원료가 있을 때 | 빈 배열이어도 ‘없음 확인’으로 처리하지 않는다. 파우더B의 콩발효추출물 계열 원료는 하위 원료 확인 전까지 ‘판정 대기’ 이유로 표시한다. |
| 동물성 원료 | 제품 API `component.{구성품}.animal_ingredient` | 없음 / 있음(종류) + 확인 상태 | 동물성 원료 관련 위생서류 판단 시 | 떡볶이떡-S와 파우더B 모두 ‘없음 / needs_check / usable:false’. 관련 서류는 ‘판정 대기’로 두고, 확인할 구성품과 이유를 보여준다. 떡 증숙 여부와 따로 판단한다. |
| VEGAN 표시 | 완제품 포장 (제품 API에 칸 없음) | 표시 있음 / 없음 | 참고 | 참고 정보로만 보여준다. 동물성 원료 ‘없음’의 확인 근거로 쓰지 않는다. |
| 통관상 원산지 (프랑스) | 별도 확인값 (입력 경로는 미정) | 국가명 | 프랑스 RITA 조치 조회 시 | 예시 API에 없음. 미입력이면 원산지에 따라 달라지는 조치만 ‘판정 대기’로 둔다. |
| 수입 예정일 (프랑스) | 별도 확인값 (입력 경로는 미정) | 날짜 (YYYY-MM-DD) | 프랑스 RITA 조치 조회 시 | 예시 API에 없음. 미입력이면 날짜 기준 조치를 ‘판정 대기’로 둔다. |
| 공식 자료 조회 결과 | 각 공식 기관 자료 (보관·갱신 방식은 미정) | 근거명·링크·확인일 | 각 판정 항목 | 조회에 실패하면 영향받은 항목에 ‘조회 실패’와 재시도를 안내한다. ‘해당 없음’으로 처리하지 않는다. |

컵또떡 예시 자료에서 확인 상태를 따로 볼 내용은 다음과 같다.

- 파우더B는 한글 포장의 ‘콩발효추출물’과 자문보고서의 ‘양조간장분말’이 같은 현행 원료인지 확인이 필요하다. 예시 API의 값은 영어 라벨을 옮긴 ‘대두발효추출물’이다. 하위 원료가 무엇인지도 확인이 필요하다.
- 표시된 배합에는 동물성 원료가 없고, 완제품 포장에는 VEGAN 표시가 있다. 그래도 API 확인 상태가 `needs_check`이므로 동물성 원료는 확인된 값으로 쓰지 않는다.

### 국가별 조회 순서

앞 단계의 정보가 없으면 그 단계에 의존하는 결과만 대기한다. 이미 판단할 수 있는 다른 항목은 계속 보여준다.

**싱가포르**

| 순서 | 조회 내용 | 공식 기관·근거 자료 | 사용하는 입력 |
|---|---|---|---|
| 1 | HS 6자리 | 제품 API `export.hs6`, 없으면 과거 신고 이력(190190) | HS 6자리, 과거 한국 신고코드 |
| 2 | 세관 8자리 HS 코드 후보와 수입 관할기관(CA) | 싱가포르 세관(Singapore Customs) HS/CA 제품코드 자료 | 1의 6자리, 떡 가공 상태 |
| 3 | SFA 제품코드와 식품분류 | 싱가포르 식품청(SFA) 수입 식품 제품코드·분류 자료 | 2의 후보, 구성품 정보 |
| 4 | 원재료·가공 상태·지정 품목 조건 | SFA 수입 식품 요건 자료 | 원재료, 하위 원료, 동물성 원료, 증숙 여부, 보관 조건 |
| 5 | 수입자 자격과 선적별 서류 | 싱가포르 세관 수입허가(CCP) 안내, SFA 수입자 등록·면허 안내 | 수입자 정보(입력 경로 미정) |

**프랑스**

| 순서 | 조회 내용 | 공식 기관·근거 자료 | 사용하는 입력 |
|---|---|---|---|
| 1 | HS 6자리 | 제품 API `export.hs6`, 없으면 과거 신고 이력(190190) | HS 6자리, 과거 한국 신고코드 |
| 2 | EU CN 8자리·TARIC 10자리 후보 | EU 집행위원회 TARIC·CN 자료 | 1의 6자리, 떡 가공 상태 |
| 3 | 품목 설명·통관상 원산지·수입 예정일 기준 조치 | 프랑스 세관(DGDDI) RITA | 2의 후보, 통관상 원산지, 수입 예정일 |
| 4 | 구성품별 배합·포장·보관 조건에 따른 위생서류 판단 | EU 공식 통제 규정과 복합식품 반입 요건, 프랑스 국경 검사 안내 | 원재료, 하위 원료, 동물성 원료, 보관 조건, 포장 |

완제품 제조국(대한민국, 확인됨)과 통관상 원산지는 서로 다른 값이다. 통관상 원산지는 별도 확인값으로 받는다.

## 4. 출력과 저장

- 화면에 보여줄 값
  - 현지 품목코드: 싱가포르 8자리 HS 코드, 프랑스 CN 8자리·TARIC 10자리를 ‘후보’로 표시한다. 출처(제품 API / 과거 신고 이력)도 함께 표시한다. 확정 코드처럼 표시하지 않는다.
  - 체크리스트의 한 줄에는 다음을 표시한다.
    - 서류·절차명
    - 적용 상태
    - 준비 담당자
    - 시점(사업자 단위 / 선적별)
    - 판단 이유
    - 부족한 정보
    - 공식 근거와 확인일
  - 적용 상태는 ‘필수 / 판정 대기 / 해당 없음’ 세 가지다.
    - ‘후보’는 품목코드에만 쓰고 서류 상태에는 쓰지 않는다.
    - ‘필수’는 이 서류가 필요하다는 판단이다. 실제 서류를 다 준비했다는 ‘준비 완료’와는 다른 뜻이다. 준비 완료 표시는 저장 방식이 정해질 때까지 미정이다.
  - 확인일은 공식 자료를 확인한 날짜다. 실제 확인 전에는 ‘미확인’으로 표시한다.

**기본 선적서류 (두 나라 공통, 목록 제목)**

- 동물성 원료 판정이 바뀔 때의 동작
  - 두 구성품 모두 비동물성으로 확인된 경우(`confirmed`)
    - 동물성 원료 때문에 생기는 서류만 ‘해당 없음’으로 바꾼다.
    - 비동물성 식품에 적용될 수 있는 별도 검사 요건은 계속 판단한다. 함께 ‘해당 없음’으로 바꾸지 않는다.
  - 동물성 원료가 확인된 경우
    - 원료의 종류·가공·보관 조건을 국가별 규칙과 다시 대조한다.
    - 아래는 판단 경로를 설명하기 위한 가정이다. 컵또떡의 실제 성분이 아니다.
      - 싱가포르: 실제 육류나 동물성 지방이 소량 들어 있으면, SFA 평가에 필요한 원산지·배합비·공정 자료를 확인한다.
      - 프랑스: 유청이 섞인 복합식품이 식품안전상 상온 운송·보관이 가능하고 일반 육가공품·초유 제품이 없는 경우에는 수입자 확인서 경로다. 일반 육가공품이 든 복합식품은 공식 위생증명서 경로다. 두 경로는 서로 다르다. 그 밖의 세부 조건은 아래 EU 근거에서 확인한다.
        - EU 복합식품 반입 요건: [위임규정 (EU) 2022/2292](https://eur-lex.europa.eu/eli/reg_del/2022/2292/oj)
        - 수입자 확인서 양식: [이행규정 (EU) 2020/2235](https://eur-lex.europa.eu/eli/reg_impl/2020/2235/oj)
- 근거 표시 방법
  - 판정 근거로 쓴 값은 확인된 제품 값(`confirmed`), 과거 신고 이력, 별도 확인값으로 구분해 표시한다.
  - 참고로만 보여주는 값(`usable:false`)에는 ‘확인 필요’ 또는 ‘미확인’ 표시를 붙인다.
- 수출 대상국 전환·재접속 시 기대하는 동작
  - 규제 탭에 들어올 때 공통 상단에서 선택한 수출 대상국을 유지한다. 제품이 없으면 체크리스트만 대기한다.
  - 공통 상단에서 수출 대상국을 바꾸면 제품 선택은 유지한다. 수출 대상국별 서류와 근거는 새 수출 대상국 기준으로 다시 계산해 표시한다.
  - 체크 완료 저장, 결과 이력, 재접속 시 복원은 팀 합의 전까지 미정이다.

## 5. 다른 탭·공통 기능과의 연결

합의한 연결만 적는다. 저장소 전체 연동표는 담당자 간 합의 후 작성한다.

| 가져오거나 제공하는 값 | 읽거나 쓰는 쪽 | 확인 상태·단위 | 합의 상태 |
|---|---|---|---|
| 규제용 제품 정보와 확인 상태 (`GET /api/products/{제품코드}?for=규제&external=1`의 `fields`, `components`) | 제품 관리 탭(채주현) → 규제 탭이 읽음 | `status`(confirmed / needs_check / missing / not_applicable), `usable`, g·개 | 합의 |
| 국가별 실제 제조사 또는 현지 책임사업자 표시 요건. 사용자가 라벨 탭에서 제조사를 ‘공개 안 함’으로 고르면, 해당 국가 규칙에 따라 경고하는 방안 | 규제 탭 → 라벨 탭 | 전달 필드·방식 미정 | 제안·미정 |
| CI·PL 준비 필요성 안내 | 규제 탭 → 서류 작성 화면 | 작성 화면 연결과 완료 상태 공유 방식 미정 | 제안·미정 |

## 6. 오류와 검증

| 상황 | 사용자에게 기대하는 결과 | 확인 방법·실제 결과 |
|---|---|---|
| 공통 상단에서 싱가포르를 고른 상태로 규제 탭에 들어와 컵또떡 선택 | 수출 대상국 싱가포르가 유지된 채 수입허가(CCP)가 ‘필수 · 현지 수입자·신고대리인 · 선적별’로 표시된다. UEN과 SFA 등록·면허는 사업자 자격으로 따로 표시된다. | 미검증 |
| 공통 상단에서 수출 대상국을 싱가포르에서 프랑스로 전환 | 컵또떡 선택은 유지된다. 프랑스 목록(DELTA IE, ENS, EORI 등)이 표시되고, 싱가포르 CCP는 남지 않는다. | 미검증 |
| HS 6자리 미입력 (`export.hs6` 비어 있음) | 기본 선적서류(CI, PL, 운송서류)는 계속 표시된다. 과거 신고 이력이 있으면 현지 품목코드 ‘후보’만 출처 ‘과거 신고 이력’으로 보여준다. HS와 이력이 모두 없으면 코드 조회만 대기한다. | 미검증 |
| 동물성 원료 값이 ‘없음’이지만 `usable:false` | 동물성 원료 관련 서류가 ‘판정 대기’로 표시된다. 확인할 구성품(떡볶이떡-S, 파우더B)과 이유(확인 필요 상태, 파우더B 하위 원료 미확인)가 보인다. | 미검증 |
| 이후 두 구성품 모두 비동물성으로 확인 | 동물성 원료 관련 서류만 ‘해당 없음’으로 바뀐다. 비동물성 식품 대상 별도 검사 요건과 다른 항목의 상태는 그대로 유지된다. | 미검증 |
| 공식 자료 조회 실패 | 영향받은 항목에만 ‘조회 실패’와 재시도 안내가 보인다. 해당 항목은 ‘해당 없음’으로 바뀌지 않는다. 다른 항목은 계속 표시된다. | 미검증 |
| 공통 상단에서 수출 대상국을 고른 상태로, 제품 선택 전 진입 | 공통 상단에서 고른 수출 대상국은 그대로 유지된다. 체크리스트만 대기 상태로 표시되고 제품 선택 안내가 보인다. 수출 대상국을 다시 고르라는 안내는 나오지 않는다. | 미검증 |

완료 기준은 사용자 동작으로 작성한다. 예를 들어 제품 탭에서는 “원재료 자료가 부족한 제품을 저장하고 다시 열면 해당 항목에 ‘확인 필요’가 표시된다”처럼 적는다. 미실행 사례는 ‘미검증’으로 남긴다.
