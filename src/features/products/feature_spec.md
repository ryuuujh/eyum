# E:YUM 제품 등록·관리 (부속물품 HS코드 포함) 기능 명세

담당자 채주현 · 최종 수정일 2026-11-26 · 상태 초안 (제품 등록·관리는 화면 시안과 저장 규칙 팀 공유 완료, 부속물품은 옵션 구조 합의 중)

## 1. 목적과 범위

- **쓰는 사람과 상황:** 혜윰 수출 담당자가 수출할 식품과 부속물품(카탈로그 · 포장상자 · 굿즈)의 기본 정보를 한 번 등록해 두고, 규제 · 라벨 · 서류 탭이 같은 값을 가져다 쓰게 한다. 자료가 여러 파일과 메일에 흩어져 있고, 일부 값은 제조사에 물어봐야 채울 수 있는 상황을 전제로 한다.
- **이 탭에서 끝낼 수 있어야 하는 업무**
  1. 제품을 구성품 단위로 등록 · 수정한다 (구성품별 원재료 · 100g당 영양 · 품목보고번호).
  2. 칸마다 확인 상태를 남기고, 비어 있거나 확인이 필요한 칸을 "할 일"로 모아 본다.
  3. 제조사 · 담당자에게 보낼 자료 요청 목록을 엑셀로 내려받고, 채워 온 파일을 다시 올려 반영한다.
  4. 글자 PDF · 메일 본문을 올려 AI가 칸을 채우게 하고, 사람이 확인한 뒤 저장한다.
  5. 제품 정보 정리본(값만, 외부 공유용 옵션)을 엑셀로 내려받는다.
  6. 부속물품을 등록하고 HS코드(HS6 · HSK10)를 찾아 사람이 확정한다.
- **이번 시연 범위:** 또떡EZ · 컵또떡 등록과 상세 · 할 일 · 엑셀 내려받기 · 요청 목록 다시 올리기 · 자료 읽기(AI), 다른 탭 연결 통로. 부속물품 HS 찾기는 함께 개발 중.
- **범위 밖:** 국가 선택(제품 정보는 수출국과 무관하게 같다), 알레르기 판단 · 반올림 · 현지어 번역 · 수입자 · 로트 번호(라벨 탭), 규제 적합 판정(규제 탭), 선적별 수량(서류 탭), CoA 등록 · 번역(CoA 탭).

## 2. 사용자 흐름

| 단계 | 사용자 동작 | 화면에 표시할 결과 |
|---|---|---|
| 1 | 제품 관리 메뉴 진입 | 제품 목록 (제품명 · 구성품 수 · 할 일 개수 · 최근 수정일). 제품이 없으면 "+ 새 제품 등록" 안내 |
| 2 | + 새 제품 등록 → 직접 입력 또는 자료 올리기 | 등록 화면 5개 탭 (기본 정보 / 구성품 / 영양성분 / 표시 정보 / 수출·물류). 탭 이름 옆에 빈 칸 수. 빈 칸 안에 예시와 "어디서 찾는지" 힌트 |
| 3 | 값을 바로 못 채우는 칸에 답변 선택 | 값 적음 / 제조사에 확인 중 / 아직 정하지 않음 / 해당 없음 / 모름 |
| 4 | 저장 | 바뀔 내용을 먼저 보여 주고("저장 전 확인할 내용") 저장. 제품 상세로 이동 |
| 5 | 제품 상세의 할 일 탭 확인 | 한 줄 요약 → [먼저] 모아야 할 자료 → [다음] 확인이 필요한 값 → 기다리는 중. 줄마다 [자료 올리기] [직접 입력] 버튼, 필요한 탭(규제 · 라벨 · 서류) 표시 |
| 6 | 자료 요청 목록 내려받기 → 제조사가 채운 파일 다시 올리기 | 바뀔 값 미리보기 → 확인 후 반영 |
| 7 | 자료 올리기 (글자 PDF · 메일 본문) | 1) 코드가 글을 뽑고 민감정보를 지운 결과를 보여 줌 → 2) 사람이 확인 · 수정 → 3) AI가 칸 추출 → 4) 미리보기에서 칸별로 골라 반영 |
| 8 | 제품 정보 정리본 내려받기 | 시트(기본 / 구성품 / 원재료 / 영양 / 표시 / 수출) 선택, 외부 공유용(주소 · 단가 · 위탁 제조사 빼기) 선택 |
| 9 | 부속물품 등록 · HS 찾기 | 물품명 · 재질 · 용도 등 입력 → HS 후보 → 사람이 HS6 · HSK10 확정 (세부는 미정, 7장) |

## 4. 출력과 저장

- **화면:** 제품 목록, 제품 상세(할 일 / 제품 정보 / 영양성분), 등록 · 수정 화면. 제품 영양성분은 저장하지 않고 구성품 값(100g당 × 중량)으로 계산해 보여 준다.
- **파일:** 제품 정보 정리본(.xlsx, 값만, 빈 값은 "—", 인쇄 가로 맞춤), 자료 요청 목록(.xlsx, 미확인 · 확인 필요 칸만, 숨긴 칸 ID 열로 다시 올리기 가능).
- **저장:** 저장 버튼 한 번 = DB 함수 `save_product` 한 번 = 트랜잭션 하나 (중간 실패 시 전부 취소). 저장 전에 바뀔 내용을 보여 준다.
- **확인 상태 (field_status, 칸마다 1줄)**

  | 상태 | 화면 표시 | 언제 |
  |---|---|---|
  | confirmed | 확인됨 | 사람이 적거나 고친 값, "맞아요" 체크한 값 |
  | needs_check | 확인 필요 | AI가 채운 값, 추정값 |
  | missing | 미확인 | 빈 칸. 기다리는 이유(제조사에 확인 중 / 아직 정하지 않음 / 모름) · 누구에게 · 요청한 날 함께 저장 |
  | on_hold | 보류 | 근거가 부족해 쓰지 않기로 한 값 (예: 실중량 없는 간장 100g당 영양) |
  | not_applicable | 해당 없음 | 할 일에서 빠지는 유일한 상태 |

  - 기다리는 중인 칸도 할 일 개수에 계속 포함하고, 7일이 지나면 다시 "지금 할 일"로 올린다.
- **AI 값과 사람 값 구분:** AI가 채운 값은 확인 필요로 저장하고 근거 자료(source_documents)를 연결한다. 사람이 확인하면 확인됨으로 바뀐다.
- **민감정보:** 주소 · 전화 · 이메일 · 단가 · 배합비는 AI로 보내기 전에 코드(`sanitize`)가 지우고, 지우지 못한 흔적이 남으면 AI를 부르지 않는다. 스캔 PDF · 사진은 받지 않는다. OpenAI 호출은 서버에서만 한다.
- **국가 전환 · 재접속:** 제품 화면은 상단 수출국 선택과 무관하게 항상 같다. 저장한 값은 다시 열어도 그대로이고, 누가 수정할 수 있는지는 미정(7장).

## 5. 다른 탭·공통 기능과의 연결

| 가져오거나 제공하는 값 | 읽거나 쓰는 쪽 | 확인 상태·단위 | 합의 상태 |
|---|---|---|---|
| 제품 · 구성품 · 원재료 · 영양 · 포장 값 (칸마다 값 + 상태 + usable) | 규제 탭 | 확인됨 · 해당 없음만 usable, 나머지는 "아직 모름" | 합의 (11/25 규제 담당) |
| 표시 정보 · 영양 · 원재료 · 함량 기준 · 포장 크기 · 완제품 제조원 | 라벨 탭 | 위와 같음. 확인 안 된 값은 비워 두고 라벨 탭이 누락 경고 | 합의 (11/25 라벨 담당) |
| 제품명 · HS6/HSK10 · 단가 · CTN · 팔레트 · 제조국 · 제조원 | 서류 탭 (CI·PL · 수출신고) | 위와 같음 | 칸 구성 합의, 단가 포함 범위 미정 |
| 부속물품(옵션) · HS · 가액 | 서류 탭 | 선적 단위가 옵션이 됨 | 미정 (옵션 구조 합의 후 서류 담당과) |
| 연결 통로 `GET /api/products`, `GET /api/products/[code]?for=규제|라벨|서류&external=1` | 각 탭 | external=1이면 주소 · 단가 · 위탁 제조사 제외. 다른 탭은 DB를 직접 읽지 않고 이 통로를 쓴다 (11/26 확정) | 통로 구현 완료, 팀 적용 전 |
| 나라별 제조사 표기 의무 | 규제 탭 → 라벨 탭 | 규제표 칸 | 규제 담당에 요청함 |
| 공통 함수: field_status · sanitize · HsCodePicker | 제품 · 부속물품 | HsCodePicker 입력(물품명 · 종류 food/accessory · 속성 · 기존 코드) / 출력(HS6 · HSK10 · 확정일 · 확정자) | 합의 (Claude: field_status · sanitize, GPT: HsCodePicker · HS 검토 이력) |

## 6. 오류와 검증

| 상황 | 사용자에게 기대하는 결과 | 확인 방법·실제 결과 |
|---|---|---|
| 정상 입력 | 또떡EZ를 등록하고 다시 열면 구성품 3개 · 원재료 · 영양 합산이 그대로 보이고 직접 적은 칸은 "확인됨" | 미검증 (이 저장소에 코드 넣기 전. 이전 작업 폴더에서 로컬 Postgres로 새 등록 · 수정 통과) |
