# E:YUM 식품 라벨링 기능 명세

- 담당: 박진혁
- 작성 기준: 2026-11-26 / KITA AX 마스터 2기 3차 프로젝트
- 담당 브랜치: `feature/labels`
- 명세 위치: `src/features/labels/feature_spec.md`
- 현재 개발 기준: 독립 실행형 FOOD LABEL STUDIO V3-E3 (Windows 테스트 수정 반영본)
- 문서 상태: 팀 공유 및 협의용 개정 초안

> 현재 독립형에서 구현한 기능과 팀 통합 앱에서 앞으로 구현할 기능을 구분한다. 라벨은 검토용 초안이며 법적 적합성이나 실제 인쇄·수출 가능성을 보증하지 않는다.

## 1. 목적과 범위

제품 관리에 등록된 제품의 구성품·원재료·영양성분·기존 라벨 문안·포장 정보를 이용해 수출 대상국에 맞는 식품 라벨 초안을 작성하고, 누락 사항 및 규제 검토 근거를 확인하는 기능이다. 국가별 표시 언어와 규제 차이를 반영하여 반복적인 문안 작성 및 확인 업무를 줄이고, 사람이 최종 검토할 수 있도록 한다.

- 대상국: 프랑스(FR, 프랑스어), 싱가포르(SG, 영어).
- 목표 출력: FR 개별포장·외박스, SG 개별포장·외박스 총 4종.
- 검토 화면: 외국어 문구별 한국어 뜻, 입력 누락, 규제 점검 결과와 근거.
- 보조 기능: 공식 법령·공지 수집, 변경 후보 비교·관리, 관리자 조회 정책 관리.
- 범위 외: UAE 규정 구현, 법률상 최종 승인, 실제 인쇄 적합성 보증, 자동 규칙 배포.

### 1.1 현재까지의 개발 진전

| 개발 단계 | 구현 내용 | 상태 |

| V3-B | FR/SG 라벨 생성 및 기초 규제 점검 | 독립형 구현 |

| V3-D / R2 | 법령 자료 저장·비교, 변경 후보 분류·검토 이력 | 독립형 구현 |
| V3-E1 / E2 | 관리자 인증·설정, 수동 조회 제한·공통 잠금 | 독립형 구현 |

| STEP 2 | 가상 제품 등록 원자료 연결 및 국가별 문구 작성 | 설계 제안, 미구현 |
| STEP 3 | 개별포장·외박스 4종, 문구별 한국어 뜻 | 목표 설계, 독립형 미구현 |
| 팀 앱 이식 | Next.js·Supabase 및 실제 제품 관리 데이터 연결 | 미구현·미검증 |

기존 PREP에는 별도 Node 미리보기 검증 기록(5/5)이 있으나 이는 독립형 V3-E3나 팀 Next.js 앱의 실제 4종 라벨 구현 완료를 뜻하지 않는다.

| 표시 강조 및 물리적 요건 | 일부 무당·저당·감미료 문구 검토, 소형 포장 등 확인 안내 | 인쇄·마크·글자 크기 및 모든 강조 조건 자동 승인 미지원 |
| 법령 변경 감지 | 공식 자료 저장·판본 비교·후보 분류, 원문 및 검토 기록 | 변경 후보는 확정 개정이나 규칙 승인과 다름 |

규칙 범위는 V3-B 기초 규칙과 후속 R2/R3 보완에 한정된다. 기존 94개 체크리스트 전체가 자동 구현되었다는 의미는 아니다.

## 2. 사용자 흐름

| 단계 | 사용자 동작 | 목표 화면 결과 | 현재 상태 |
|---|---|---|---|
| 1 | 공통 국가 선택에서 FR 또는 SG 선택 | 현재 국가·표시 언어 확인 | 독립형 국가 선택 및 생성 지원, 팀 연결 미검증 |
| 2 | 등록 제품 선택 | 공통 원자료 및 확인 필요 항목 표시 | 기존 샘플 선택 지원, 실제 등록 연결 예정 |
| 3 | 국가별 문구 작성·수정 | 확정 원자료와 편집 가능한 초안 분리 | STEP 2 예정 |
| 4 | 개별포장 또는 외박스 선택 | 외국어 초안, 한국어 뜻, 점검 결과 및 근거 | STEP 3 예정 |
| 5 | 누락·번역·규제 근거 검토 | 확인 사유 표시, 사람의 최종 검토 | 일부 경고 구현, 저장·승인 범위 미정 |

국가 전환 시 선택 제품을 유지하는 흐름을 팀 앱에서 검증한다. 원자료 오류는 제품 관리에서 수정하고, 국가별 표현 변경은 라벨링 탭에서 처리하는 방향을 제안한다.

## 3. 입력

### 3.1 공통 원자료와 라벨링 데이터의 경계

| 입력 | 제공처(제안) | 형식·단위 | 누락 시 처리 |
|---|---|---|---|
| 제품 ID·확정 상품명·일반 식품명 | 제품 관리 | 공통 ID, 문자열, 언어 구분 | 제품 연결·명칭 확인 |
| 구성품 및 원재료 | 제품 관리 | 계층 구조, 등록 순서, 구성품 내용량 및 수량 | 순서·세부 성분 확인 |
| 알레르기·교차접촉 | 제품 관리 | 성분 유형 및 확인 상태 | 없음과 미확인 구분 |
| 표기 함량 | 제품 관리 | 수치·단위 및 구성품/완제품 기준 | 기준 누락 시 표시 보류 |
| 영양성분 원자료 | 제품 관리 | 항목·수치·단위·기준량·조제 상태 | 0으로 대체하지 않고 환산 보류 |
| 개별포장·외박스 | 제품 관리(출처 협의) | 순내용량·입수량·외박스 총량·치수·용도 | 해당 포장만 확인 요청 |
| 기존 라벨 문안 | 제품 관리 | 언어·포장·항목별 원문, 출처 | 원문 요청, 자동 추정 금지 |
| 제조·수출업체 및 원산지 | 제품 관리(관리 주체 협의) | 확정 명칭·주소·국가 | 확인 요청 |
| LOT·제조일·기한 | 생산분 데이터(제공처 미정) | 실제 날짜·종류·기한 기간 구분 | 기간에서 실제 날짜 임의 생성 금지 |
| 현지 책임사업자 | 수출 관련 데이터(제공처 미정) | 국가·역할·명칭·주소 | 국가별 확인 요청 |
| 국가별 번역·수정 문구 | 라벨링 | 언어·항목·포장별 초안 및 확인 상태 | 번역 또는 사람 검토 요청 |

팀 공통 기준에 따라 배합비는 수집하지 않고 구성품과 원재료 순서를 유지한다. 공통 원자료의 확인됨·확인 필요·미확인·보류 상태를 보존하는 방향이며 실제 전달 필드명은 협의한다. 첨부 파일명과 추출 결과는 별개로 취급한다.

### 3.2 회사 자료 검토에서 반영할 요구사항

회사 제공 영어 라벨 자료에는 제품 3종, 각 개별포장과 외박스 문안(총 6종), 제품명·내용량·원재료·사용법·보관법·주의사항·제조일·기한·원산지·제조/수출/수입유통업체의 12개 항목이 확인되었다.

- 구성품 내부에 하위 원재료가 있는 구조를 유지해야 한다.
- 개별포장과 외박스는 내용량뿐 아니라 알레르기 안내 및 조리 문구도 달라질 수 있다. 단순 복제하지 않는다.
- 기존 영어 문안은 SG 초안의 원자료로 활용하되 SG 규정 충족으로 간주하지 않는다.
- 기존 수입·유통업체 정보는 대상국용 정보로 자동 전용하지 않는다.
- 실제 생산일·기한 유형·LOT·포장 면적·일부 하위 성분 등은 추가 확인이 필요하다.
- 검토한 DOCX에는 영양성분표가 확인되지 않았다. 별도 원자료를 확보해야 한다.

실제 제품명·업체 정보·회사 수치·원본 문서는 공유 저장소와 이 명세에 포함하지 않는다.

### 3.3 STEP 2 가상 등록 입력(제안)

| 항목 | 개발용 가상 값 |
|---|---|
| 제품 ID / 상품명 | `demo_registered_001` / DEMO GRAIN KIT |
| 식품명 | 곡물 간편조리 키트 |
| 개별포장 / 외박스 | 150 g / 12개, 총 1,800 g |
| 구성품 1 | 곡물면 120 g: 밀가루 → 쌀가루 → 정제수 → 소금 |
| 구성품 2 | 소스 30 g: 정제수 → 사과 퓌레 → 설탕 → 대두분 → 소금 |
| 영양성분 기준 | 100 g당: 240 kcal, 지방 4 g, 포화지방 1 g, 탄수화물 42 g, 당류 6 g, 단백질 9 g, 나트륨 480 mg 등 가상 값 |
| 누락 검증 | LOT, 실제 기한 날짜, 포장 크기, 현지 사업자 미입력 |
| 현지어 | FR/SG 검토용 문구 별도 준비, 원자료 수정 없음 |

위 값은 회사 실측치가 아닌 신규 개발·테스트용 제안이다. 기존 9개 샘플을 유지하면서 가상 등록 제품 한 건을 별도 입력 변환기로 연결한다. 기존 생성기의 제품·생산분·수출 설정 구조를 재사용하고, 외박스 출력 연결은 STEP 3으로 분리한다. 신규 데이터 구조와 버전명(V3-F1 후보)은 구현 전 확정한다.

## 4. 출력과 저장

### 4.1 국가별 출력 목표

| 국가 | 개별포장 | 외박스 | 언어 |
|---|---|---|---|
| FR | 제품별 순내용량·표시 문구 | 입수량·총량·포장별 문구 | 프랑스어 |
| SG | 제품별 순내용량·표시 문구 | 입수량·총량·포장별 문구 | 영어 |

포장별 용도와 적용 규정을 확인하여 표시 항목을 결정한다. 네 결과에 모든 동일 필드가 법적으로 필수라는 의미는 아니다.

- 검토 화면에는 외국어 문구별 한국어 뜻과 규제 점검 근거를 표시하며, 실제 인쇄 문구와 분리한다.
- 확정 상품명·원재료 순서·원본 수치·단위를 보존한다. 국가별 표시 기준에 따른 환산값은 원본과 구별한다.
- 영양성분 항목명은 고정 용어 사전 중심으로 현지화하고 수치 환산 및 반올림은 검증된 계산 로직을 사용한다.
- 원문, 검토용 번역, 사람이 확정한 문구를 구분한다. 현지어 수정이 공통 원자료를 변경하지 않도록 한다.
- 입력 누락 또는 근거 부족은 확인 필요·미확인·보류로 안내하며, 자동 법적 승인으로 처리하지 않는다.
- 팀 앱의 초안 저장 시점, 수정 이력, 내보내기 형식, 최종 승인 권한은 미정이다.

### 4.2 보조 기능: 법령 변경 감지 및 관리자 운영

| 자료 출처 | 기존 구현 | 운영상 한계 |
|---|---|---|
| EU EUR-Lex / Cellar | 1169/2011 통합판 후보 조회, EN/FR XHTML 수집 및 비교 | 통합판에 반영되지 않은 개정·기타 규정의 완전 탐지 아님 |
| 프랑스 Légifrance | PISTE Sandbox 수동 인증·검색 및 후보 저장 | 운영 API 미검증, 검색 범위 제한 |
| SG SFA | Circulars·Newsroom·Food Alerts 3종 RSS 수집·비교 | 공지 소멸을 법령 삭제로 판단하지 않음 |
| SG SSO | 공식 PDF 수동 등록·조항 및 부속서 비교 | 자동 수집 제한, 새 판본 수동 확보 필요 |

독립형에는 SQLite 법령 자료/후보 및 관리자 DB가 분리되어 있다. 후보 상세 및 검토 기록을 확인할 수 있으나 조회나 후보 검토만으로 라벨 규칙을 자동 변경하지 않는다.

V3-E3 운영 정책(독립형 기본값):

- 자동 조회 기본 OFF. 활성화 시 KST 지정 시각(기본 09:00), 날짜당 최대 1회. EU 및 활성 SFA 피드 대상. 별도 예약 실행기와 켜져 있는 호스트 필요.
- 수동 조회 하루 기본·최대 3회, 최소 30분 간격. 여러 출처를 묶은 작업은 1회로 집계. 작업 횟수와 실제 HTTP 시도 수는 구별한다.
- 요청 간격 기본 1초, 일부 오류 기본 1회 재시도, 리다이렉트도 집계. 출처별 자체 HTTP 한도 적용 가능.
- 429 응답 시 해당 출처 중단, Retry-After 적용 또는 기본 30분 차단. 공식 제공자 할당량은 미확인이다.
- 관리자 인증·설정, 최근 작업 상태, 출처별 이유, 다음 예정 시각, HTTP 사용량 확인 지원.
- 팀 앱에 해당 기능을 어떤 화면·서버·스케줄러로 이식할지는 별도 협의한다. 독립형 로컬 운영 기능을 팀의 Supabase 권한 체계로 확정한 것은 아니다.

독립형의 `schemas/`, `adapters/`, `services/label_generator.py` 등은 구현 참고 및 검증 기준으로 활용한다. 팀 앱에서는 `src/features/labels/`에 기능 로직, `src/app/labels/page.tsx`에 화면을 두는 방향이며 공통 UI·DB 변경은 관련 담당자와 먼저 협의한다. Python Flask 개발본 전체를 그대로 팀 앱에 복사하는 것이 확정된 것은 아니다.
