# 유정현 프롬프트 기록

## 2026-11-26 공통환경 초기 준비

- 요청은 E:YUM 앱의 로컬 공통환경을 준비하고 기존 디자인 초안과 기능 명세 양식을 이어 사용하는 것이다.
- 전날 정한 이름 규칙, 사람이 직접 커밋·푸시하는 원칙, 제품과 규제 탭 간 확인 상태 전달을 개발 문서에 반영했다.
- 정확한 AI 모델 ID와 전체 탭의 공통 식별자·권한은 후속 합의 사항으로 표시했다.

## 2026-11-26 공통환경 적용 및 첫 실행

- 준비 폴더 `eyum_setup_20261126`의 공통환경을 `eyum` 루트에 적용하고 첫 실행을 확인해 달라는 요청을 받았다.
- 준비본 26개 파일을 빈 앱 루트에 복사하고 원본과 해시를 대조했다. 팀 지정 버전으로 패키지를 설치하고 `package-lock.json`을 생성했다.
- `npm run dev`가 기존 `AGENTS.md` 끝에 Next.js 안내 블록을 자동 추가했다. 앱 소스는 준비본과 동일하다.

## 2026-11-26 데모 기반 메뉴와 화면 구조

- 실제 개발 폴더 `eyum`에서 `git apply --check`가 통과해 `eyum_navigation.patch`를 적용했다. 수동으로 병합할 충돌은 없었다.
- 데모의 상단 국가 선택을 공통으로 사용하고, 제품 관리를 홈 바로 아래에 두기로 했다.
- 부속물품 HS코드를 제품 관리에 묶고 수출신고서 화면을 분리했다. 팀원이 각 탭의 페이지 파일에서 개발을 시작하도록 업무별 진입점을 마련했다.
- 이번 범위는 공통 화면 구조다. 탭별 업무 데이터의 세부 연동은 후속 협의 사항이다.

## 2026-11-26 수출국 선택 드롭다운

- 모든 탭에서 왼쪽에 ‘수출국’ 라벨을 두고, 처음에는 ‘국가 선택’, 선택 후에는 국가명을 표시해 달라는 요청을 받았다.
- 공통 헤더의 두 링크를 기본 HTML `select`로 교체했다. 싱가포르와 프랑스 중 하나를 고르면 현재 주소의 `country` 값이 바뀌며, 각 탭은 기존처럼 이 값을 메뉴 링크에 전달한다.

## 2026-11-26 왼쪽 메뉴의 수출국 소제목과 업무 번호

- 홈과 제품 관리 사이에 작은 여백을 두고 제품 관리 아래에 구분선을 배치했다. 구분선 다음에 선택 국가를 소제목으로 표시하고, 기존 순서대로 국가별 업무 다섯 개에 ①~⑤를 붙였다.
- 소제목은 공통 화면이 상단 드롭다운에 전달하는 국가 값을 함께 사용한다. 국가를 고르기 전에는 ‘국가별 수출 업무’를 표시한다.

## 2026-11-26 사이드바 구분선 위치 변경

- 요청에 따라 구분선을 홈과 제품 관리 사이로 옮겼다. 제품 관리와 국가별 업무 소제목 사이는 위쪽 여백으로 띄웠고 개발 문서에도 같은 순서를 반영했다.

## 2026-11-26 사진 기준 사이드바와 로그인 관리 메뉴

- 첨부 사진에 맞춰 HYEYUM 로고 옆에 접기 버튼을 두고, 홈 아래에 구분선과 수출국 소제목을 배치했다. 업무 다섯 개는 원형 번호로 표시하고 현재 업무는 연녹색으로 강조했다.
- 제품 관리와 겹친 검은 N은 Next.js 개발 표시여서 설정에서 숨겼다. 요청에 따라 사이드바 하단에는 제품 관리 바로 아래에 로그인 관리를 일반 메뉴로 추가했다. 로그인 관리는 인증 연동 전 준비 화면으로 연결한다.
- 후속 요청에 따라 제품 관리 위에 있던 구분선을 제품 관리와 로그인 관리 사이로 옮겼다.

## 2026-11-26 대시보드 레퍼런스를 반영한 공통 디자인과 UI

- 팀원이 같은 디자인으로 화면을 개발하도록 첨부 레퍼런스와 실제 홈 화면을 디자인 규칙에 연결했다. 새 탭에서 `FeatureScreen`과 `Panel`을 조합하는 예시, 반응형 배치와 키보드 검증 기준을 추가했다.
- Pretendard 가변 서체와 라이선스를 앱에 포함했다. 글자 크기, 색, 간격, 카드 테두리와 그림자를 공통 CSS에 정의했다. 레퍼런스의 밝은 청색 배경과 흰 카드를 사용하고 주요 동작은 혜윰 녹색으로 표시했다.
- 홈에는 수출 물류 배너와 국가별 업무·제품·부속물품 바로가기를 배치했다. 업무 탭 전체에서 공통 제목과 카드를 사용하고 좁은 화면은 메뉴를 접은 상태로 시작한다.
- 후속 요청에 따라 공통 디자인을 초기 권장안으로 명시했다. 담당자가 자기 화면의 글꼴·색·배치·컴포넌트를 자유롭게 바꾸고, 다른 탭에 영향을 주는 공통 UI 변경만 관련 담당자와 조율하도록 팀 지침을 정리했다.

## 2026-11-28 제품 관리 가상 예시 교체

- 제품 관리 PR의 최신 코드를 `feature/git_rules`에 가져와 로컬 seed와 DB 미연결 화면의 예시를 가상 제품으로 교체해 달라는 요청을 받았다. 첫 작업에서는 AI가 ‘테스트 단호박 수프 키트’를 골랐다. 수출 선택 1개, 여러 구성품, 확인됨·확인 필요·미확인 상태를 유지해 할 일, 다른 탭 조회, 엑셀 내려받기를 시연할 수 있도록 했다.
- 제품과 구성품 3개의 원재료·원산지·영양 수치, 영어 라벨 문구 5줄을 가상으로 작성했다. 코코넛 크림의 한 포 실중량은 비워 두어 100g당 영양 계산 보류를 확인할 수 있다.
- 제품 명세에 검증 기준을 적었다. 입력 화면·코드·테스트에 복사된 실제 제품 예시를 교체하고, 채주현의 이전 기록에서는 당시 수행한 검사와 결과를 보존하며 식별값을 일반화했다.
- Git에는 가상 예시를 공유하고 팀 공통 DB에는 검토한 마이그레이션만 적용한다는 합의를 Git·DB 규칙에 반영했다.
