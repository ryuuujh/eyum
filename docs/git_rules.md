# E:YUM Git 협업 규칙

기능 작업은 `feature/<작업명>`에서 하고 `develop`에 PR을 보낸다. 통합 검증 후 발표할 버전을 `main`에 반영한다. 공통 개발환경·DB·PR 검토는 유정현이 주담당, 채주현이 부담당이다.

## 커밋

- 하나의 작업 목적을 한 커밋으로 묶고 관련 개인 프롬프트·검증 기록을 포함한다.
- 스테이징·커밋·푸시는 담당자가 직접 수행한다. AI는 변경 요약과 커밋 제목을 제안한다.
- 제목은 `유형: 한국어 변경 내용` 형식으로 작성한다.

| 유형 | 예시 |
|---|---|
| `feat` | `feat: 제품 구성품 등록 화면 추가` |
| `fix` | `fix: 자료 미확인 상태가 저장 후 사라지는 문제 수정` |
| `style` | `style: 제품 입력 표의 열 간격 조정` |
| `refactor` | `refactor: 구성품 영양값 환산 함수 분리` |
| `docs` | `docs: 프롬프트 수정 전후 검증 결과 기록` |
| `test` | `test: 간장 실중량 누락 시 환산 보류 사례 추가` |
| `chore` | `chore: 공통 TypeScript 검사 설정 추가` |
| `data` | `data: 제품 등록용 가상 구성품 예시 추가` |

## 커밋과 PR 전 확인

- [ ] 담당 기능 브랜치와 변경 범위를 확인했다.
- [ ] 기능을 검증하고 실행하지 못한 항목은 기록했다.
- [ ] 관련 기능 명세와 개인 작업 기록을 갱신했다.
- [ ] 실제 환경 설정, 인증 정보, 개인정보, 기업 원본 자료, 로컬 DB와 빌드 결과가 변경 목록에서 제외됐는지 확인했다.
- [ ] PR에 공통 패키지·환경변수·DB·다른 기능에 미치는 영향을 적었다.
