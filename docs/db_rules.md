# E:YUM 공통 DB

서비스 DB는 Supabase PostgreSQL을 사용한다. 공통환경 초기에는 로컬 앱부터 실행하고, 로그인·저장 기능을 연결할 때 팀 개발용 프로젝트를 준비한다.

## 변경 절차

1. 각 탭 담당자가 필요한 값, 자료 출처, 단위, 확인 상태, 저장 시점을 기능 명세에 적는다.
2. 공통 식별자와 다른 탭에서 읽을 값은 관련 담당자와 협의한다. 기업·사용자·제품·부속물품의 ID 규격과 전체 탭 연동표는 미정이다.
3. 테이블과 권한 변경은 `supabase/migrations/`의 SQL로 작성하고 PR에서 함께 검토한다. 테이블·열은 영문 소문자 `snake_case`를 사용한다.
4. 검토한 변경을 공유 환경에 적용하는 주담당은 유정현, 부담당은 채주현이다. 데이터 삭제·초기화 실험은 로컬 또는 전용 테스트 환경에서 진행한다.

## 저장값과 권한

- 제품 관리에서는 원재료 순서를 유지하며, 배합비는 수집하지 않는다. 제품 표기 함량은 구성품 기준인지 완제품 기준인지 구분한다.
- 제품 → 규제 탭은 각 값에 `확인됨`, `확인 필요`, `미확인`, `보류` 중 하나를 함께 전달한다. 예를 들어 원재료표가 없는 구성품의 동물성 원료는 `미확인`으로 보관한다.
- 부속물품 자체 ID와 HS코드를 구분하는 방향을 검토한다. 부속물품 등록 정보와 선적별 수량의 연결 방식은 서류 담당과 확정한다.
- 대표·직원의 서비스 내 조회·등록·수정 범위는 로그인·저장 기능 구현 전에 정리한다. 개발팀의 DB 관리 권한은 서비스 사용자의 업무 권한과 별도로 부여한다.
- 발표 환경은 개발 데이터와 구분한다. 기업 이관 시 저장 구조·변경 이력·운영 절차를 함께 전달하고 서비스 관리 주체를 혜윰 측과 확인한다.
